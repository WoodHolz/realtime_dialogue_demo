# 需求说明：催授权 AI 外呼（容联云 + Voice Agent）

> 状态：草案｜场景素材：`docs/bg_check_voice_docs`（A1 催授权）

## 1. 目标

对外提供**一通电话任务接口**：合作方部门发起外呼 → 我方 Voice Agent + 容联云打电话 → 用「催授权」剧本完成对话 → **通话结果回传给调用方**。

中间电话通道由容联云承担；业务 API、对话 AI、结果与录音由我方 Voice Agent 服务承担。

## 2. 角色与边界

| 角色 | 职责 |
|------|------|
| 合作方系统 | 调用我方 API 发起任务、轮询或接收回调拿结果 |
| 我方 Voice Agent | 对外业务接口、催授权对话、结果汇总、三轨录音归档 |
| 容联云 | PSTN 外呼 / 通话媒体；需双向音频（AI ↔ 用户） |

不做：合作方直连容联云坐席台；不做「仅语音通知放音」单通产品形态。

## 3. 主流程（简）

```
合作方 ──POST 发起外呼──► Voice Agent
                              │
                              ├─ 容联云：拨打被叫
                              ├─ 接通：双向音频进催授权 Agent
                              ├─ 挂机：汇总结果 + 归档三轨录音
                              │
合作方 ◄──轮询 / 回调──────┘
```

## 4. 合作方接口（对外）

### 4.1 发起通话

- `POST /api/v1/calls`
- 核心入参（示意）：`phone`、`scenario=urge_auth`、`candidate_name`、`client_name`、`external_id`、`callback_url`（可选）及催授权所需业务字段
- 立即返回：`call_id`、`status`

### 4.2 获取结果

- **轮询**：`GET /api/v1/calls/{call_id}`
- **回调**（若传入 `callback_url`）：通话结束后 `POST` 结构化结果

### 4.3 结果内容（最小集）

- 任务状态：`queued` / `dialing` / `in_call` / `completed` / `failed`
- 业务结果标签（催授权）：如已承诺去填、自称已填、改约、放弃、拒接/未接通、拒绝配合等
- `result_summary`：一句话摘要
- `external_id`：原样回传
- 录音访问信息：见 §5（URL 或对象存储 key）

话术与分支依据：`docs/bg_check_voice_docs` 中 A1 催授权深挖结论（合规开场、送达确认、未收到闭环、改约/放弃等）。首版场景固定为 **催授权**；其它场景后续扩展。

## 5. 录音要求（双通道 / 三轨）

中间录音必须能**按说话方分离**，便于数据分析，不只混音。

**每一通有效通话产出 3 个录音文件：**

| # | 轨 | 内容 |
|---|----|------|
| 1 | AI 侧单轨 | 仅 Agent / TTS 播出音频 |
| 2 | 用户侧单轨 | 仅被叫人上行音频 |
| 3 | 合流 | AI + 用户对齐后的混合轨（便于试听） |

约束：

- AI 轨与用户轨为**独立声道/文件**（双通道分离录制），时间轴可对齐（同一 `call_id` + 起止时间戳）
- 格式约定：建议 WAV/PCM 或统一采样率转码后的标准格式；元数据含 `call_id`、`external_id`、时长、采样率
- 结果接口中返回三轨引用（下载 URL 或存储路径）；未接通等无媒体时可为空

实现侧在 Agent 边界分别落盘 AI TTS 与用户 RTP 上行，再合成合流（见 `backend/sip/recording.py`）。

## 6. 对接容联云（我方需就绪）

- 产品形态：**SIP 直连外呼**（TCP 5060 INVITE）+ 本进程 RTP（PCMU）↔ Voice Agent；非 CONNECTOR / WebRTC 软话机 / forkstream
- 我方提供给容联：外呼源公网 IP、RTP UDP 端口段（如 10000–10049）
- 容联提供给我方：SIP 对端、主叫 ANI、被叫前缀、测试号白名单
- 联调脚本：`scripts/sip_min_call.py`；业务入口：`POST /api/v1/calls`
- **号码池（已开通示意）**
  - 主叫（ANI）可送：`01080435740`
  - 被叫前缀：`a1`（例：`138xxxx` → API 被叫 `a1138xxxx`）
  - 外显号池：`02180639544` …（见 `.env.example` → `SIP_DISPLAY_NUMBERS`）
- 鉴权与白名单：按容联要求配置出口 IP

拨号由 `backend/outbound/dial.py` 自动加 `a1` 前缀；合作方只需传真实手机号。媒体与对话由 `backend/sip/` 完成。

## 7. 非目标（首版不做）

- 多场景剧本同时上线（仅催授权）
- 合作方自定义话术全文覆盖（仅业务槽位注入）
- 本地无公网环境下的生产级媒体对接（需部署公网 Agent）

## 8. 验收要点

1. 合作方可只调我方 API 完成「发起 → 拿结果」，无需对接容联。
2. 接通后为**双向**实时对话，剧本为催授权。
3. 通话结束后结果经轮询或回调可达，含业务标签与摘要。
4. 每通有效通话具备 **AI 单轨、用户单轨、合流** 三份录音且可关联同一 `call_id`。
